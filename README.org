#+title: Pi config

My [[https://github.com/badlogic/pi-mono][Pi]] setup, packed into a Nix flake so it can follow me without becoming a small archaeological dig.

* Run it

#+begin_src sh
nix run github:suderman/pi
#+end_src

It uses =~/.pi/agent= when that exists. Otherwise it starts Pi with this repo's config in a temporary writable directory.

* Included bits

- Themes and keybindings that suit me.
- MCP setup for Chrome DevTools, Context7, grep.app, and MiniMax.
- Small extensions for Hyprland controls, MMX web search, a calmer footer, and occasional nonsense while Pi thinks.
- Commit prompts and a few local skills.

API keys stay outside this repo. Set whichever provider variables your setup needs, such as =CODEX_LB_API_KEY= or =MINIMAX_API_KEY=.

* Pi Lens paths

The launcher sets these defaults when using =~/.pi/agent=:

| Variable              | Path                                    | NixOS persistence |
|-----------------------+-----------------------------------------+-------------------|
| =PI_LENS_CONFIG_PATH= | =~/.config/pi/pi-lens.json=              | storage           |
| =PI_LENS_HOME=        | =~/.local/state/pi/pi-lens=              | scratch           |
| =PILENS_DATA_DIR=     | =~/.local/state/pi/pi-lens/projects=     | scratch           |

Config stays in this repo's backed-up directory. Logs, managed tools, worklogs,
install choices, and diagnostic decisions share Pi's existing scratch-backed
state directory. No extension-specific persistence mount is needed. Lens mixes
caches with that state, so those caches also survive reboots but are not backed
up. Pi's =~/.cache= data can remain disposable.

Explicit environment overrides win. The standalone launcher honors
=XDG_CONFIG_HOME= and =XDG_STATE_HOME=; the NixOS wrapper uses its Pi config and
state roots. Setting =PILENS_DATA_DIR= also keeps new runtime writes out of legacy
workspace =.pi-lens/= directories. Without =~/.pi/agent=, the fallback keeps Lens
data in the temporary tree instead.

* Pi FFF paths

FFF's two LMDB databases default to these paths:

| Variable           | Path                                  | NixOS persistence |
|--------------------+---------------------------------------+-------------------|
| =FFF_FRECENCY_DB=  | =~/.local/state/pi/fff/frecency=       | scratch           |
| =FFF_HISTORY_DB=   | =~/.local/state/pi/fff/history=         | scratch           |

Frecency and query history are useful between sessions but are not
configuration, so they use Pi's existing scratch-backed state directory. FFF
does not write a disk index. Its file index lives in memory and can be rebuilt.

Explicit environment overrides still win. Without =~/.pi/agent=, the standalone
launcher puts both databases in its temporary agent tree.

* Notes

This is personal config, not a polished distribution. Borrow whatever is useful. If an extension says it is consulting the void, it is probably still working.
